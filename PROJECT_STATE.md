# AviorCMS Android — состояние проекта (читать в начале каждой новой сессии)

> расхождений не нашлось, фикс счётчиков из §4 применён тут же).

## 1. Что это

Внутреннее Android-приложение для сотрудников сервиса АВИОР (владелец,
админы, инженеры-приёмщики — та же ролевая модель, что в веб-CRM).
Работает через **Mobile API** веб-CRM: `https://cms.avior.moscow/api/mobile/`.
Полная спецификация API — в репозитории `cms_avior`, файл
`docs/MOBILE_API.md` (там же — актуальный «промт для Gemini» с описанием
дизайна/экранов, если понадобится перегенерировать что-то через Gemini).

## 3. Что собрано (в репозитории, версия Вейса — идентична по структуре)

Полноценный проект с нуля — из-за проблем со сборкой у Gemini
(см. §5 «Известные грабли») собирали заново, аккуратно:

- **API-слой**: `ApiModels.kt` (data-классы строго под реальные названия
  полей из `docs/MOBILE_API.md` — `report_url`, `receipt_url`,
  `client_name` и т.д., через `@SerializedName`), `ApiService.kt`
  (Retrofit-интерфейс всех эндпоинтов), `ApiClient.kt` (единственный
  экземпляр Retrofit на всё приложение + `AuthInterceptor`, подставляющий
  токен в каждый запрос — важно: НЕ создавать второй Retrofit где-то ещё,
  иначе запросы оттуда уйдут без токена и будет выглядеть как «просит
  войти заново», хотя токен есть).
- **`TokenStore`** — `EncryptedSharedPreferences`, синхронное чтение
  (без гонки при старте приложения).
- **`CmsViewModel`** — единая точка состояния (`StateFlow`): заказы,
  клиенты, справочники (`meta`), логин/логаут, `refreshData()`.
- **Экраны** (`ui/`): `LoginScreen`, `DashboardScreen` (счётчики по
  статусам — аналог `.pipeline` на веб-панели), `OrderListScreen`,
  `AddOrderScreen`, `OrderDetailScreen` (документы/статус/шаринг),
  `ClientsScreen`, `Common.kt` (иконки устройств/цвета статусов/EmptyState).
- **Тема** (`ui/theme/`) — фирменные цвета АВИОР (`#1C2436` navy,
  `#E0B45C` gold), Light/Dark.
- **`build.gradle.kts`** — явные версии зависимостей (не через `libs.`
  каталог — раз он мог быть криво настроен раньше, лучше явно).

## 4. Известный баг и готовый фикс (проверить, применён ли)

**Симптом**: счётчики на главном экране «живут своей жизнью» — то 0,
то частичные данные.

**Причина**: `DashboardScreen` при заходе вызывал `viewModel.refreshData()`,
которая по инерции подгружала последний использованный фильтр статуса
(если до этого заходили в список заказов с фильтром) вместо полного
списка.

**Фикс** (проговорено с Вейсом, готов к применению): в `DashboardScreen.kt`
заменить
```kotlin
LaunchedEffect(Unit) { viewModel.refreshData() }
```
на
```kotlin
LaunchedEffect(Unit) {
    viewModel.loadMeta()
    viewModel.loadOrders(null)
    viewModel.loadClients(null)
}
```
**Статус: фикс применён 19.08** (был не применён в первой залитой версии
— заменено на месте, запушено этим же коммитом). Если увидите старый
код `viewModel.refreshData()` в `DashboardScreen.kt` где-то ещё — значит,
это регресс, вернуть на вариант ниже.

## 5. Известные грабли сборки (не наступать снова)

Всё это уже один раз ломало сборку у Gemini, разбирали долго — если
увидите похожее в коде Вейса или будете что-то генерировать заново:

- `compileSdk { version = release(37) }` — **невалидный/выдуманный
  синтаксис**. Правильно: `compileSdk = 34` (простое число).
- `buildTypes { release { optimization { enable = false } } }` —
  тоже невалидно. Правильно: `isMinifyEnabled = false`.
- `androidx.browser:browser` как `project("androidx.browser:browser")`
  — ломает Gradle (пытается найти как локальный путь). Если нужен
  Custom Tabs — `implementation("androidx.browser:browser:1.8.0")`.
  В итоге в приложении Custom Tabs не используются вообще (документы
  открываются через `Intent.ACTION_SEND`/`ACTION_SENDTO`), так что
  этой зависимости в проекте быть не должно.
- `Icons.AutoMirrored.Filled.ArrowBack` (и `.Send`, `.Assignment`) —
  **не резолвится** в текущей версии `material-icons-extended` в
  проекте Вейса (несовпадение версий с BOM) — ошибка «receiver type
  mismatch». Использовать `Icons.Filled.ArrowBack` и т.п. (deprecated-
  предупреждение — это нормально, не ошибка сборки).
- `json_encode()`-подобных проблем в Kotlin нет (это специфика PHP из
  веб-CRM), но по аналогии — если где-то видите вставку строки с
  кавычками прямо в `onclick`-подобную конструкцию, проверяйте
  экранирование.
- Android Studio один раз падал с «An internal error has occurred» —
  причина была именно в сломанном `androidx.browser` (см. выше),
  плюс не помешает `File → Invalidate Caches` после правки
  `build.gradle.kts`.

## 7. Что дальше

1. Собрать в Android Studio, установить на телефон, проверить, что

2. Дальше — обычная разработка: правки через этот чат или напрямую,
   не забывать `git pull`/`git push` (см. памятку по командам, которую
   Вейс получил отдельно).
3. Обновлять этот файл после каждого значимого изменения — так же,
   как `cms_avior/PROJECT_STATE.md`.
